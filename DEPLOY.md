# Как разместить сайт и получить ссылку

Посетитель сможет открыть сайт в обычном браузере на компьютере или телефоне. Устанавливать ему ничего не нужно. Node.js запускается на хостинге — компьютере, который обслуживает сайт в интернете.

**Текущая версия требует серверного хостинга.** Простая загрузка папки `dist/` на GitHub Pages не обеспечит генерацию, хранение эталонов, проверку и чат.

## Пример: Render Web Service

Названия кнопок могут немного отличаться в зависимости от языка и версии кабинета. Эти шаги описывают размещение; они не означают, что сайт уже опубликован.

1. Убедись, что актуальные изменения сохранены в GitHub-репозитории `Weeqee05/exam-generator`.
2. Зарегистрируйся на [render.com](https://render.com/) и подключи GitHub.
3. Создай **New → Web Service**. Выбери репозиторий `exam-generator`. Если сервис предлагает Static Site, вернись и выбери Web Service: приложению нужен работающий сервер.
4. Укажи настройки:

| Поле | Что указать |
| --- | --- |
| Name | Любое свободное имя, например `praktikum-assistant` |
| Branch | `main` |
| Root Directory | Оставить пустым — корень репозитория |
| Runtime | Node |
| Build Command | `node --check server.mjs` |
| Start Command | `npm start` |
| Health Check Path | `/api/status` |

5. В разделе **Environment** добавь:

| Переменная | Значение |
| --- | --- |
| `NODE_VERSION` | `24` |
| `HOST` | `0.0.0.0` |
| `LLM_BASE_URL` | `https://sharellm.net/v1` |
| `LLM_MODEL` | `qwen3.8-flash` или точное имя доступной модели у провайдера |
| `LLM_API_KEY` | Твой ключ API |

`PORT` обычно выдаёт сам хостинг — не заменяй его без необходимости. `EMBEDDED_PREVIEW` оставь выключенным: он нужен только для встроенного окна рабочей среды, а не для обычного сайта.

6. Выбери тариф и нажми **Deploy Web Service**. Проверяй актуальные цены в кабинете до заказа. Бесплатные тарифы могут засыпать, иметь ограничения времени ответа и очищать временное состояние при перезапуске.
7. После успешного запуска открой выданную HTTPS-ссылку. Адрес будет похож на `https://твоё-имя.onrender.com`. Собственный домен покупать необязательно.
8. Проверь обычную генерацию, правильный и неправильный ответы, подсказку, показ решения и чат. Затем проверь создание одного задания через ИИ. Если модель настроена, но недоступна по тарифу или балансу, сайт покажет ошибку.

Для другого Node.js-хостинга используются те же настройки: Node.js 24, `npm start`, `HOST=0.0.0.0`, порт платформы и серверные переменные API. Таймаут HTTP-запроса на платформе должен позволять дождаться ответа модели: сервер ждёт до 240 секунд, браузер — до 250. Если тариф обрывает запросы раньше, выбери платформу или тариф с достаточным временем ожидания либо более быструю доступную модель.

После подключения автодеплоя новые коммиты в `main` обычно запускают новое размещение. Проверяй статус последнего деплоя: сохранение в GitHub и успешный запуск на хостинге — разные действия.

## Где находится ключ и почему он не переносится сам

Ключ хранится только на сервере. Локальный файл `.env.connection.json` этой рабочей среды не включён в GitHub и Docker, поэтому новый хостинг не получит его из репозитория. Один раз задай ключ в **Environment** хостинга. Значения переменных нельзя добавлять в HTML или JavaScript страницы.

Другой совместимый API настраивается через `LLM_BASE_URL` и `LLM_MODEL`. Адрес должен использовать HTTPS и поддерживать `/chat/completions` и JSON-ответы. По умолчанию используется ShareLLM с `qwen3.8-flash`. Для этой модели сервер читает SSE-поток, игнорируя внутренние рассуждения и возвращая браузеру готовый JSON.

Сохранение секретного поля не подтверждает доступ к модели. `/api/status` сообщает только, заполнены ли настройки. Реальная проверка выполняется генерацией или отдельной командой `npm run test:llm` и может расходовать баланс провайдера. У хостинга и сервиса ИИ разные тарифы.

## Что важно знать об учебной версии

История, переписка и эталоны находятся в памяти **одного процесса**. Они очищаются при перезапуске, новом деплое или пробуждении с перезапуском сервиса. Срок сессии ограничен; постоянной базы данных и регистрации пока нет. Для этой версии запускай один экземпляр сервера. Несколько реплик потребуют общего хранилища.

Сессионная cookie отделяет историю одного браузера от другого, но не является системой регистрации. Если сайт нужен только тебе и преподавателю, настрой ограничение доступа средствами хостинга. Для открытого сайта с платным API понадобятся общий контроль расходов и полноценная авторизация; текущие ограничения запросов в одном процессе не заменяют их.

## Локальный запуск в контейнере

Если установлен Docker:

```bash
docker build -t praktikum .
docker run --rm -p 127.0.0.1:8000:8000 praktikum
```

На своём компьютере открой `http://localhost:8000`. Без переданного API-подключения доступен режим шаблонов. Для ИИ передай серверные переменные средствами Docker или подключи локальный `.env.connection.json` только для чтения по пути `/app/.env.connection.json`. Не добавляй ключ в Dockerfile.

Docker — дополнительный вариант. Для первого размещения достаточно Node.js Web Service без самостоятельной настройки контейнера.
