# Как разместить сайт и получить ссылку

Посетитель сможет открыть сайт в обычном браузере на компьютере или телефоне. Устанавливать ему ничего не нужно. Node.js запускается на хостинге — компьютере, который обслуживает сайт в интернете.

**Текущая версия требует серверного хостинга.** Простая загрузка папки `dist/` на GitHub Pages не обеспечит генерацию, хранение эталонов, проверку и чат.

## Пример: Render Web Service

Названия кнопок могут немного отличаться в зависимости от языка и версии кабинета. Эти шаги описывают размещение; они не означают, что сайт уже опубликован.

1. Убедись, что актуальные изменения сохранены в GitHub-репозитории `Weeqee05/exam-generator`.
2. Зарегистрируйся на [render.com](https://render.com/) и подключи GitHub.
3. Создай **New → Web Service**. Выбери репозиторий `exam-generator`. Если сервис предлагает Static Site, вернись и выбери Web Service: приложению нужен работающий сервер.
4. Укажи настройки:

| Поле | Что указать |
| --- | --- |
| Name | Любое свободное имя, например `examen-plus` |
| Branch | `main` |
| Root Directory | Оставить пустым — корень репозитория |
| Runtime | Node |
| Build Command | `node --check server.mjs` |
| Start Command | `npm start` |
| Health Check Path | `/api/status` |

5. В разделе **Environment** добавь:

| Переменная | Значение |
| --- | --- |
| `NODE_VERSION` | `24` |
| `HOST` | `0.0.0.0` |
| `LLM_BASE_URL` | `https://generativelanguage.googleapis.com/v1beta/openai` |
| `LLM_MODEL` | `gemini-3.1-flash-lite` или точное имя доступной модели у провайдера |
| `LLM_API_KEY` | Твой ключ API |

`PORT` обычно выдаёт сам хостинг — не заменяй его без необходимости. `EMBEDDED_PREVIEW` оставь выключенным: он нужен только для встроенного окна рабочей среды, а не для обычного сайта.

6. Выбери тариф и нажми **Deploy Web Service**. Проверяй актуальные цены в кабинете до заказа. Бесплатные тарифы могут засыпать, иметь ограничения времени ответа и очищать временное состояние при перезапуске.
7. После успешного запуска открой выданную HTTPS-ссылку. Адрес будет похож на `https://твоё-имя.onrender.com`. Собственный домен покупать необязательно.
8. Проверь обычную генерацию, правильный и неправильный ответы, подсказку, показ решения и чат. Затем проверь создание одного задания через ИИ. Если модель настроена, но недоступна по тарифу или балансу, сайт покажет ошибку.

Для другого Node.js-хостинга используются те же настройки: Node.js 24.5 или новее, `npm start`, `HOST=0.0.0.0`, порт платформы и серверные переменные API. Таймаут HTTP-запроса на платформе должен позволять дождаться ответа модели: сервер ждёт до 240 секунд, браузер — до 250. Если тариф обрывает запросы раньше, выбери платформу или тариф с достаточным временем ожидания либо более быструю доступную модель.

После подключения автодеплоя новые коммиты в `main` обычно запускают новое размещение. Проверяй статус последнего деплоя: сохранение в GitHub и успешный запуск на хостинге — разные действия.

Перед первым размещением выполни `npm test`. Дополнительная команда `npm run test:browser` проверяет интерфейс на отдельном сервере без ключей; для неё нужны Python Playwright и Chromium. `npm run test:llm -- qwen` или `npm run test:llm -- gemini` отдельно проверяет настроенного провайдера настоящими запросами (максимум пять обращений за запуск). Вариант `npm run test:llm -- qwen --limits` проверяет три задания по пределам. Версию применённого кода можно проверить по заголовку `X-App-Version` у `/api/status`; это не запрос к модели.

После размещения проверь также свою тему, переключение модели, обновление страницы с черновиком и повторную попытку после ошибки. В финальной локальной проверке Qwen прошёл полный сценарий, а Google после генерации вернул 503; такую ошибку провайдера следует отличать от ошибки размещения. Подробности находятся в `docs/EXPERIMENTS.md`.

## Где находится ключ и почему он не переносится сам

Ключ хранится только на сервере. Локальный файл `.env.connection.json` этой рабочей среды не включён в GitHub и Docker, поэтому новый хостинг не получит его из репозитория. Один раз задай ключ в **Environment** хостинга. Значения переменных нельзя добавлять в HTML или JavaScript страницы.

Другой совместимый API настраивается через `LLM_BASE_URL` и `LLM_MODEL`. Адрес должен использовать HTTPS и поддерживать `/chat/completions` и JSON-ответы. Для текущего подключения используется прямой Google Gemini: адрес `https://generativelanguage.googleapis.com/v1beta/openai`, модель `gemini-3.1-flash-lite`. Это совместимый формат API Google, поэтому нативный адрес `:generateContent` здесь не нужен. Ключ Google задаётся в `LLM_API_KEY`. Ранее использовавшийся ShareLLM остаётся возможным вариантом с явно заданными адресом и моделью, но текущая конфигурация обращается к Google. Модель `gemini-flash-latest` при проверке отвечала 503, поэтому автоматически заменять выбранную модель этим псевдонимом не следует.

Сохранение секретного поля не подтверждает доступ к модели. `/api/status` сообщает только, заполнены ли настройки. Реальная проверка выполняется генерацией или отдельной командой `npm run test:llm` и может расходовать баланс провайдера. У хостинга и сервиса ИИ разные тарифы.

## Две модели в одном сайте

Для Gemini достаточно основного `LLM_API_KEY` и настроек из таблицы. Для выбора Qwen дополнительно задай на сервере `QWEN_API_KEY` — ключ ShareLLM; при необходимости `QWEN_BASE_URL=https://sharellm.net/v1` и `QWEN_MODEL=qwen3.8-27b`. Перезапусти сервис после изменения. Ключи относятся к разным провайдерам и не взаимозаменяемы.

При обновлении старого подключения проверь `QWEN_MODEL`: прежний `qwen3.8-flash` больше не предлагается ShareLLM. В Render → Environment явно заданное старое значение нужно заменить на `qwen3.8-27b` или удалить переменную, чтобы работало значение по умолчанию из кода. После сохранения Render должен перезапустить сервис.

Пользователь выбирает Gemini или Qwen в окне параметров и рядом со списком текущих заданий. Без ключа модель недоступна в списке. Ключи не передаются посетителям. Наличие модели в списке подтверждает конфигурацию, а не гарантирует доступность внешнего сервиса в момент запроса. При сбое выбранной модели скрытого переключения на другую нет.

## Что важно знать об учебной версии

История, переписка и эталоны находятся в памяти **одного процесса**. Они очищаются при перезапуске, новом деплое или пробуждении с перезапуском сервиса. Срок сессии ограничен; постоянной базы данных и регистрации пока нет. Для этой версии запускай один экземпляр сервера. Несколько реплик потребуют общего хранилища.

Сессионная cookie отделяет историю одного браузера от другого, но не является системой регистрации. Если сайт нужен только тебе и преподавателю, настрой ограничение доступа средствами хостинга. Для открытого сайта с платным API понадобятся общий контроль расходов и полноценная авторизация; текущие ограничения запросов в одном процессе не заменяют их.

## Локальный запуск в контейнере

Если установлен Docker:

```bash
docker build -t examen-plus .
docker run --rm -p 127.0.0.1:8000:8000 examen-plus
```

На своём компьютере открой `http://localhost:8000`. Без переданного API-подключения доступен режим шаблонов. Для ИИ можно использовать `docker run --rm --env-file .env -p 127.0.0.1:8000:8000 -e HOST=0.0.0.0 examen-plus`; здесь `--env-file` читает твой файл, а `HOST` разрешает подключение через порт контейнера. Другой вариант — подключить локальный `.env.connection.json` только для чтения по пути `/app/.env.connection.json`. Не добавляй ключ в Dockerfile.

Docker — дополнительный вариант. Для первого размещения достаточно Node.js Web Service без самостоятельной настройки контейнера.

Контроль темы вероятностей: `npm run test:llm -- gemini --probability` (настоящие запросы, максимум пять обращений к модели). Ошибка `MODEL_SUSPENDED` означает, что ShareLLM приостановил модель: настройка Render это не исправляет, можно вручную выбрать Gemini. Ошибка 503 от Gemini означает временную недоступность сервиса Google; сайт не переключает модель автоматически.
