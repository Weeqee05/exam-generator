# Как получить обычную ссылку на сайт

Сайтом можно пользоваться в Chrome, Safari, Firefox и других современных браузерах, в том числе на телефоне. Устанавливать программу посетителю не нужно.

Сейчас подготовлен код приложения. Для постоянной ссылки его нужно разместить на хостинге. Запуск в среде Codex и публикация этой среды сохраняют рабочее место разработчика; постоянный адрес сайта на хостинге настраивается отдельно. Изменения здесь ещё не отправлены в GitHub и не обновляют существующий сайт в Sites.

## Вариант с сервером Node.js

Подойдёт хостинг с Node.js 18 или новее и HTTPS, например сервис типа Web Service. Подключи репозиторий после проверки и сохранения изменений в GitHub.

Настройки сервиса:

| Поле | Значение |
| --- | --- |
| Корневая папка | Корень репозитория |
| Версия Node.js | 24 LTS, либо другая поддерживаемая версия >=18 |
| Установка / сборка | Не требуется: внешних пакетов и сборки нет. Если команда обязательна: `node --check server.mjs` |
| Команда запуска | `npm start` |
| Переменная `HOST` | `0.0.0.0` |
| Переменная `PORT` | Значение, выданное хостингом; по умолчанию 8000 |
| Проверка доступности | `GET /api/status`, ожидается HTTP 200 |

После запуска хостинг выдаст HTTPS-ссылку. Проверь создание варианта, подсказки, скачивание и перезагрузку страницы. Некоторые бесплатные тарифы засыпают: первое открытие после перерыва занимает больше времени.

Публикацию и доступ нужно выбрать отдельно: репозиторий с открытым кодом сам по себе не определяет доступ к сайту. Если нужен закрытый сайт для преподавателя, используй ограничение доступа на хостинге или перед сервером. Встроенной регистрации пользователей в приложении нет.

## Контейнер

В проекте есть Dockerfile. На машине с Docker:

```bash
docker build -t praktikum .
docker run --rm -p 127.0.0.1:8000:8000 praktikum
```

Это локальный запуск. На хостинге настрой HTTPS и доступ средствами выбранной платформы. Сборка контейнера и выдача сайта внутри него проверены в среде разработки; это не означает, что сайт уже размещён на хостинге.

## Подключение ИИ позже

Обычная практика уже работает без ключей. Для режима ИИ потребуется отдельный API-доступ к сервису модели, который поддерживает `/chat/completions` и `response_format: {type: "json_object"}`. Подписка ChatGPT не заменяет этот доступ.

Добавь в **секретные настройки сервера на хостинге**, затем перезапусти сервер:

| Имя | Что указать |
| --- | --- |
| `LLM_API_KEY` | Ключ сервиса. Никогда не добавляй его в GitHub, браузерный JavaScript или переписку |
| `LLM_MODEL` | Идентификатор доступной тебе модели, взятый из документации сервиса |
| `LLM_BASE_URL` | HTTPS-адрес совместимого API, по умолчанию `https://api.openai.com/v1` |

Для локального запуска под Linux/macOS можно создать `.env` из `.env.example`, заполнить его локально, а затем выполнить `set -a; . ./.env; set +a` перед `npm run dev`. Файл `.env` игнорируется Git. Никогда не включай значения ключей в инструкции или снимки экрана. Node.js 20.6+ также поддерживает `node --env-file=.env server.mjs`.

Сервер передаёт ключ только выбранному сервису. В браузер отправляется результат генерации. На сервере проверяются параметры, размер и формат ответа, число и уникальность заданий; текст модели отображается безопасно. Проверка формата не доказывает правильность решения. Код, предложенный моделью, не исполняется.

Установлены ограничения: до 10 обращений в минуту на IP, не больше двух одновременных генераций на процесс, ожидание модели до 45 секунд. Перед открытым платным API используй контроль доступа и бюджет на стороне сервиса модели; лимит в памяти одного процесса не заменяет авторизацию и общий лимит расходов. Реальный платный запрос сейчас не проверялся: ключа нет, а пользователь выбрал работу без ИИ.

## Только статический сайт

Можно разместить содержимое `dist/` на статическом хостинге: задания по шаблонам, история, промпты, скачивание и печать будут работать. Режим ИИ на таком хостинге требует отдельного серверного размещения и настройки, поэтому для будущего подключения модели удобнее вариант с Node.js.

История хранится только в браузере посетителя. На другом устройстве она не появится; очистка данных браузера удалит её. Печать / PDF открывает стандартное окно печати, где можно выбрать «Сохранить как PDF».
