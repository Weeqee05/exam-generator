# Как получить обычную ссылку на сайт

Сайтом можно пользоваться в Chrome, Safari, Firefox и других современных браузерах, в том числе на телефоне. Устанавливать программу посетителю не нужно.

Для постоянной ссылки приложение нужно разместить на хостинге. Запуск в среде Codex и публикация этой среды сохраняют рабочее место разработчика; постоянный адрес сайта на хостинге настраивается отдельно. Изменения репозитория сами по себе не обновляют существующий сайт в Sites.

## Вариант с сервером Node.js

Подойдёт хостинг с Node.js 18 или новее и HTTPS, например сервис типа Web Service. Подключи репозиторий после проверки и сохранения изменений в GitHub.

Настройки сервиса:

| Поле | Значение |
| --- | --- |
| Корневая папка | Корень репозитория |
| Версия Node.js | 24 LTS, либо другая поддерживаемая версия >=18 |
| Установка / сборка | Не требуется: внешних пакетов и сборки нет. Если команда обязательна: `node --check server.mjs` |
| Команда запуска | `npm start` |
| Переменная `HOST` | `0.0.0.0` |
| Переменная `PORT` | Значение, выданное хостингом; по умолчанию 8000 |
| Проверка доступности | `GET /api/status`, ожидается HTTP 200 |

После запуска хостинг выдаст HTTPS-ссылку. Проверь создание варианта, подсказки, скачивание и перезагрузку страницы. Некоторые бесплатные тарифы засыпают: первое открытие после перерыва занимает больше времени.

Публикацию и доступ нужно выбрать отдельно: репозиторий с открытым кодом сам по себе не определяет доступ к сайту. Если нужен закрытый сайт для преподавателя, используй ограничение доступа на хостинге или перед сервером. Встроенной регистрации пользователей в приложении нет.

## Контейнер

В проекте есть Dockerfile. На машине с Docker:

```bash
docker build -t praktikum .
docker run --rm -p 127.0.0.1:8000:8000 praktikum
```

Это локальный запуск. На хостинге настрой HTTPS и доступ средствами выбранной платформы. Сборка контейнера и выдача сайта внутри него проверены в среде разработки; это не означает, что сайт уже размещён на хостинге.

## Подключение ИИ через ShareLLM

В сервере настроены ShareLLM: `https://sharellm.net/v1` и модель с именем `agnes-2.5-flash`. Настоящее создание задания через сервер проверено 23 октября 2026 года. Для обычной практики ключ не нужен. Для ИИ доступны два способа настройки сервера.

При наличии данных подключения формата `newapi_channel_conn` сервер автоматически читает их из локального файла `.env.connection.json` в корне проекта:

```json
{
  "_type": "newapi_channel_conn",
  "url": "https://sharellm.net",
  "key": "YOUR_API_KEY",
  "model": "agnes-2.5-flash"
}
```

Поле `model` можно не указывать для ShareLLM: будет выбрана `agnes-2.5-flash`. Сервер сам добавит `/v1` к корневому адресу и прочитает файл при `npm start`, `npm run dev` и `npm run test:llm`. Данные файла имеют приоритет над `LLM_*` среды. Он игнорируется Git и Docker и недоступен посетителям сайта. Для контейнера файл можно подключить отдельным томом только для чтения по пути `/app/.env.connection.json`. При переносе проекта на другой сервер подключение переносится отдельно от кода.

Другой вариант — поля в настройках сервера на хостинге, без локального файла подключения. После изменения перезапусти сервер:

| Имя | Что указать |
| --- | --- |
| `LLM_API_KEY` | Ключ сервиса. Никогда не добавляй его в GitHub, браузерный JavaScript или переписку |
| `LLM_MODEL` | `agnes-2.5-flash` — проверенное значение для текущего подключения ShareLLM |
| `LLM_BASE_URL` | `https://sharellm.net/v1` — значение по умолчанию |

После перезапуска режим «С помощью ИИ» выбирается автоматически, если сервер видит ключ. Открытие страницы не отправляет платный запрос. Задания создаются после нажатия «Создать вариант»; до этого может отображаться предыдущий вариант по шаблонам. Если настройки есть, но ключ неверный, баланс исчерпан или сервис недоступен, сайт покажет ошибку и сохранит предыдущий вариант.

Имена переменных и адрес сервиса можно сохранять в GitHub; значение ключа — только в защищённых настройках. В среде Codex объявлено требование `LLM_API_KEY` с разрешённым назначением `sharellm.net`. Значение вводится в настройках среды. Сохранение черновика требований само по себе не добавляет ключ и не доказывает, что генерация работает. На отдельном хостинге секрет задаётся заново в его собственных настройках.

Для локального запуска под Linux/macOS можно создать `.env` из `.env.example`, заполнить его локально, а затем выполнить `set -a; . ./.env; set +a` перед `npm run dev`. Файл `.env` игнорируется Git. Никогда не включай значения ключей в инструкции или снимки экрана. Node.js 20.6+ также поддерживает `node --env-file=.env server.mjs`.

Если среда предоставляет `HTTPS_PROXY` / `HTTP_PROXY`, сервер использует их штатным механизмом Node.js. Для этого нужен Node.js 24.5 или новее; в подготовленной среде установлен Node.js 24.19.0. Проверка сертификатов сохраняется. Прокси может заменять защищённый placeholder ключа только на разрешённом HTTPS-назначении. Не копируй этот placeholder в другой сервис или локальный файл как настоящий ключ.

Имя модели должно присутствовать в `/v1/models` именно для используемого подключения. В присланном подключении `agnes-2.5-flash` прошла настоящий запрос: сервер получил задание «Найдите модуль комплексного числа z = 5 - 12i» с ответом `13`; вычисление проверено независимо. Дополнительно в Chromium через кнопку сайта создан вариант из трёх заданий; проверены подсказка, прогресс, восстановление после перезагрузки и скачивание с ответами. Решения этих трёх заданий проверены независимым вычислением. Для этого подключения используются обычные имена моделей из списка сервиса, а не режимы `auto-*`.

Для другого совместимого сервиса задай его HTTPS-адрес в `LLM_BASE_URL` и обязательно укажи соответствующую модель в `LLM_MODEL`. Нужна совместимость с `/chat/completions` и `response_format: {type: "json_object"}`. Подписка ChatGPT не заменяет API-доступ.

Сервер передаёт ключ только выбранному сервису. В браузер отправляется результат генерации. На сервере проверяются параметры, размер и формат ответа, число и уникальность заданий; текст модели отображается безопасно. Проверка формата не доказывает правильность решения. Код, предложенный моделью, не исполняется.

Установлены ограничения: до 10 обращений в минуту на IP, не больше двух одновременных генераций на процесс, ожидание модели до 45 секунд. Перед открытым платным API используй контроль доступа и бюджет на стороне сервиса модели; лимит в памяти одного процесса не заменяет авторизацию и общий лимит расходов.

`npm test` и `python tests/browser.py` используют заглушки сервиса и не тратят реальные запросы. Для явной проверки настоящего подключения после настройки ключа:

```bash
npm run test:llm
```

Команда делает один реальный запрос через сервер и создаёт одно базовое задание по комплексным числам. Это может списать средства с API-баланса. Проверяются параметры и структура результата, затем печатаются условие и ответ для независимой проверки. Отсутствие ключа, ошибка сервиса или неверный ответ дают ненулевой код завершения. Без успешного живого запроса нельзя считать подключение к выбранному сервису проверенным.

## Только статический сайт

Можно разместить содержимое `dist/` на статическом хостинге: задания по шаблонам, история, промпты, скачивание и печать будут работать. Режим ИИ на таком хостинге требует отдельного серверного размещения и настройки, поэтому для будущего подключения модели удобнее вариант с Node.js.

История хранится только в браузере посетителя. На другом устройстве она не появится; очистка данных браузера удалит её. Печать / PDF открывает стандартное окно печати, где можно выбрать «Сохранить как PDF».
