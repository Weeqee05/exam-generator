# Журнал фактических проверок

Дата: 23 октября 2026 года. Проверки относятся к версии 0.2 с серверным хранением эталонов. Они не являются исследованием общей точности языковой модели.

## Автоматические проверки без настоящего ИИ

`npm test` завершился успешно: **52 теста**, без ошибок. Отдельно выполнены независимые проверки **945 вариантов**, **5040 расчётов** и запуск **1680 заранее подготовленных учебных Python-программ**. Код пользователей и код, сгенерированный ИИ, в этих проверках не исполняется.

Проверенные сценарии:

- Генерация по выбранным параметрам, шаблоны и имитация ответа модели.
- В публичных заданиях и истории отсутствуют эталонные answer, explanation, proof и скрытые подсказки. Полный эталон выдаётся явным запросом решения.
- Верный, неверный, частично верный ответ; пустой ввод и неоднозначная запись.
- Дробь `1/2`, десятичные `0,5` и `0.50`, безопасные арифметические выражения.
- Комплексные числа; порядок не важен для множества и важен для Python-списка. Список и кортеж различаются, в том числе внутри других контейнеров.
- Краткое число не заменяет требуемое доказательство. Неподдерживаемый разбор передаётся модели либо требует уточнения.
- История чата привязана к заданию; ассистент получает предыдущие сообщения и последние попытки студента, а не эталонные поля.
- Подсказка, объяснение проще, похожее задание, явный показ решения.
- Ошибка API, таймаут, повреждённый JSON, незавершённый SSE, лимиты и повторная попытка.
- Недоступность чужого задания по ID, серверная сессия, история до 20 вариантов.
- Фильтр очевидного дословного раскрытия ответа в подсказке/проверке/чате, включая число в конце предложения. Формулы не должны ошибочно фильтроваться из-за совпавшей цифры.
- Неполная отрицательная оценка модели дополняется указанием на ошибку и следующим шагом.

Модель в этих тестах заменена сервисом-заглушкой. Эти результаты подтверждают поведение программы, а не качество настоящей модели.

## Настоящий браузер

`tests/browser.py` прошёл в Chromium на отдельном сервере без ключа. Проверены все три темы и уровня, количество заданий, ввод и повторная проверка, подсказка, решение, история и восстановление. Для простого задания Python ожидаемый результат вычислен независимо от API. ИИ-интерфейс, задержка, ошибки и чат проверены явными заглушками.

На ширинах **320, 390, 768, 1024 и 1440 пикселей** горизонтального переполнения не обнаружено, ошибок JavaScript нет. Проверены клавиатурный фокус и безопасное отображение строк, похожих на HTML.

Отдельно выполнен HTTPS-тест встроенного окна между разными сайтами с ограничением сторонних cookie: генерация → проверка → решение → история → обновление страницы. Сессия сохраняется с `HttpOnly; Secure; SameSite=None; Partitioned`. Самоподписанный сертификат использовался только у временного тестового прокси; проверка TLS провайдера в приложении не отключалась.

## Реальное подключение ShareLLM / Qwen

Использовалось существующее серверное подключение к `qwen3.8-flash` через `https://sharellm.net/v1`. Значение ключа в журнал не включается.

- Запрос списка моделей вернул HTTP 200; выбранная модель присутствует.
- Короткий служебный запрос вернул HTTP 200 и завершённый SSE-поток за 4 секунды. Это подтверждает доступность маршрута для этого короткого запроса.
- Два запуска проверки полноценной генерации с исходным лимитом 8000 токенов остановились на ошибке провайдера. Во втором запуске зафиксирован **HTTP 524 через 125 секунд**, отображаемый приложением как понятная ошибка HTTP 502.

После уменьшения лимита ответа до 2048 токенов выполнен успешный полный сценарий через настоящий сервер и провайдера:

| Операция | Результат | Время |
| --- | --- | --- |
| Создание одного базового задания | Условие получено, эталон в публичный вариант не включён | 39,2 с |
| Явный показ решения | Эталон выдан отдельным запросом, модель повторно не вызывается | менее 0,1 с |
| Проверка развёрнутого ответа | `correct`, метод `ai`; это настоящий вызов модели | 9,3 с |
| Диалог по текущему заданию | Получено объяснение первого шага без готового результата | 17,3 с |

Условие: найти модуль комплексного числа `z = 3 + 4i`. Эталон модели `5` проверен независимо: `√(3² + 4²) = √25 = 5`. При проверке сервер передал развёрнутый текст решения, чтобы пройти именно путь ИИ-оценки, а не числовой парсер.

Стандартный режим рассуждения не отключался. Для коротких операций в приложении теперь используется лимит 2048 токенов, для генерации он растёт с числом заданий до 8000. Неполный ответ по-прежнему отклоняется. Одна успешная попытка не доказывает, что меньший лимит устраняет все ошибки сервиса или сохраняет качество на любых сложных задачах. Устойчивость маршрута ShareLLM и точность на большой выборке не измерены.

Повторный запуск штатной команды `npm run test:llm` с новым лимитом снова остановился на генерации: HTTP 524 через 126 секунд. Следовательно, меньший лимит не устраняет нестабильность маршрута.

Реальное подключение генерации, проверки и чата подтверждено на одном успешном примере. В остальных сценариях использовались заглушки; успешные заглушки не включены в результаты реальной оценки модели.

## Ограничения и дальнейший эксперимент

Автоматический парсер поддерживает ограниченный набор записей и не является полноценной системой компьютерной алгебры. Оценка рассуждений моделью может быть неверной. Проверка структуры JSON и фильтр дословного ответа не обеспечивают полную смысловую правильность и не гарантируют, что модель не перефразирует готовый ответ.

Для сравнения промптов нужно заранее выбрать одинаковые условия, сохранить версию промпта, модель и дату, вручную подготовить эталоны, затем измерить долю корректных заданий и проверок, время и расход токенов. Такое сравнение на большом наборе в этой работе пока не выполнено; его результаты здесь не выдумываются.

После замены интерфейса выполнен `npm test`: 52 теста прошли, ошибок нет. Проверки шаблонных расчётов и Python-программ сохранены. В Chromium прошёл обновлённый `tests/browser.py`:

- Раздельные режимы ответа на проверку и вопроса ассистенту, пустой ввод, неверный и равнозначный числовой ответ.
- Выбор текущего задания, раздельные черновики, восстановление выбранного задания и прогресса после обновления.

- История, скачивание условий, печать без ответов, инструкция и отправка с клавиатуры.
- Ширины 320, 390, 768, 1024 и 1440 пикселей без горизонтального переполнения.

Ошибок JavaScript не обнаружено. Скриншоты в `docs/images/` получены из браузера с локальными заданиями и проверкой кодом. Сценарии внешнего ИИ имитированы; дополнительных платных вызовов при редизайне не выполнялось. Результаты прежних настоящих запросов и нестабильность ShareLLM описаны выше; изменение оформления не является проверкой качества модели.
