# Экзамен+ — ИИ-ассистент для подготовки к экзаменам

Курсовой проект: **«Разработка ИИ-ассистента для генерации и проверки практических заданий для подготовки к экзамену»**.

Пользователь выбирает тему, сложность и количество заданий, решает их самостоятельно и отправляет ответы на проверку. Ассистент объясняет ошибку, подсказывает следующий шаг и отвечает на вопросы по выбранному заданию. Готовое решение открывается отдельной кнопкой.

## Что умеет приложение

- Темы: комплексные числа, множества и отношения, основы Python.
- Три уровня сложности; от 1 до 10 заданий в варианте.
- Два источника заданий: программные шаблоны и готовая языковая модель через API.
- Ответ или ход решения прямо в диалоге, проверка и повторная попытка.
- Результат «Верно», «Неверно», «Частично верно» либо просьба уточнить неоднозначный ответ.
- Дополнительная проверка подходящих ответов кодом: в частности, равнозначные дроби и десятичные записи. Программа не исполняет введённый пользователем Python или JavaScript.
- Чат с контекстом выбранного задания и предыдущими сообщениями.
- Действия «Дай подсказку», «Объясни проще», «Покажи решение», «Дай похожее задание».
- История вариантов в рамках серверной сессии и прогресс по успешно проверенным ответам.
- Русскоязычный адаптивный интерфейс, состояния ожидания и сообщения об ошибках.

**Эталонный ответ, решение и данные вычислений не входят в ответ API генерации или истории.** Они остаются на сервере. Эталонные поля `answer` и `explanation` возвращает отдельный запрос «Покажи решение». Промпты и дополнительный фильтр сдерживают раскрытие готового ответа в подсказках и проверке; это не полная смысловая проверка произвольного текста модели. Скрыть ответ стилями на странице было бы недостаточно: его всё равно можно было бы найти в браузере.

Без API-ключа работают шаблонные задания, доступные проверки кодом, подсказки и показ решения. Свободный диалог и оценка развёрнутых рассуждений требуют модели. Если программа не может надёжно проверить ответ без ИИ, она сообщает об этом, а не выставляет выдуманную оценку.

## Новый интерфейс

Графитовый фон, лаймовый акцент и один основной диалог с ассистентом. «Экзамен+» — название сайта; тема курсовой не меняется.

[Скриншот на компьютере](docs/images/examen-plus-desktop.png) · [Скриншот на телефоне](docs/images/examen-plus-mobile.png)

1. Нажми «Новый диалог» или выбери тему на стартовом экране. В окне параметров задай тему, сложность и количество заданий. При настроенном подключении по умолчанию выбран ИИ; для работы без него доступны тренировочные шаблоны.
2. Текущее условие появится внутри диалога. Остальные задания находятся в списке справа, а на телефоне — над чатом.
3. В режиме **«Мой ответ»** отправляй ответ на проверку. В режиме **«Вопрос ассистенту»** обсуждай непонятные шаги. Enter отправляет сообщение, Shift+Enter добавляет строку.
4. Четыре быстрые кнопки дают подсказку, простое объяснение, явный показ решения или похожее задание.

Стартовый экран не создаёт задания автоматически и не обращается к модели. Кнопка «Новый диалог» открывает параметры; запрос начинается после «Создать задания». Ошибка сохраняет текущую практику и введённый текст. При переключении заданий сохраняются отдельные черновики. В истории можно открыть прежнее занятие. Скачать и распечатать можно условия всех заданий без ответов.

Прогресс и переписка с ассистентом относятся к серверной сессии. Сообщения проверки и уже открытое решение отображаются в текущей странице; после её обновления они не загружаются скрыто — решение нужно снова запросить явно. Черновики ответов и выбранное задание восстанавливаются из браузерного хранилища, когда оно доступно.

## Как устроен проект — для защиты

Приложение использует HTML, CSS, JavaScript и небольшой сервер Node.js. Фреймворка, внешних npm-пакетов и отдельной сборки нет.

1. **Браузер** показывает диалог, текущее задание и настройки, отправляет запросы серверу, отображает результаты безопасным текстом.
2. **Сервер** проверяет параметры, хранит задания с эталонами и историю сессии. Для шаблонных задач вычисляет ответ программно, для ИИ обращается к готовой модели.
3. **Проверка ответа** сначала использует код там, где сравнение однозначно. Для текстового решения сервер передаёт модели условие, эталон и ответ студента. Если данных недостаточно, требуется уточнение.
4. **Чат** получает контекст конкретного задания и предыдущие сообщения. Подсказки помогают продолжить решение. Полный эталон возвращает отдельный серверный маршрут.

Мы не обучаем собственную нейросеть: готовая модель подключается через совместимый с OpenAI Chat Completions API. Промпты задают её роль, ограничения и формат JSON. Сервер проверяет формат ответа модели; это не доказывает математическую правильность.

| Файл или папка | Назначение |
| --- | --- |
| `dist/index.html` | Разметка страницы |
| `dist/styles.css` | Оформление и мобильный вид |
| `dist/app.mjs` | События интерфейса и обращения к API |
| `dist/generator.mjs` | Проверенные шаблонные задания, темы и сложности |
| `server.mjs` | HTTP-сервер и маршруты API |
| `server/` | Подключение модели, хранение сессий и проверка ответов |
| `prompts/generation.mjs` | Промпт генерации заданий |
| `prompts/checking.mjs` | Промпт проверки ответа студента |
| `prompts/explanation.mjs` | Промпт диалога и объяснений |
| `tests/` | Автоматические и браузерные проверки |
| `scripts/verify-provider.mjs` | Отдельная проверка настоящего API |
| `docs/EXPERIMENTS.md` | Только фактически выполненные проверки |
| `DEPLOY.md` | Пошаговое размещение на хостинге |

`dist/` здесь содержит исходники страницы, несмотря на название папки. Эталонные задания хранятся в памяти процесса, а не в файлах браузера. Сессионная cookie связывает историю с браузером. Между устройствами история не синхронизируется. Перезапуск сервера очищает историю, задания и переписку; это ограничение учебной версии.

## Как запустить на своём компьютере

1. Установи **Node.js 24 LTS** с официального сайта Node.js. Вместе с ним устанавливается npm.
2. Скачай репозиторий через GitHub → **Code → Download ZIP** и распакуй. Или используй `git clone`, если знаком с Git.
3. Открой терминал в папке, где находится `package.json`.
4. Выполни:

```bash
npm start
```

5. В браузере на этом же компьютере открой **http://localhost:8000**. Пока терминал работает, сайт доступен. Для остановки нажми **Ctrl+C**.

Устанавливать npm-зависимости не нужно. Python требуется только для части тестов, для работы самого сайта он не нужен.

В облачной рабочей среде для существующего встроенного предпросмотра используется:

```bash
HOST=0.0.0.0 EMBEDDED_PREVIEW=1 npm run dev
```

Этот запуск разрешает подключение прокси среды и показ страницы во встроенном окне. Он не размещает сайт на постоянном публичном хостинге. По умолчанию встраивание заблокировано; на обычном хостинге флаг `EMBEDDED_PREVIEW` не требуется.

Открывать `dist/index.html` двойным щелчком для новой версии недостаточно: ей нужен сервер. Файлы `downloads/praktikum.html` и `downloads/praktikum.zip` относятся к прежней автономной версии 0.1 и не содержат нового ассистента. Команда `export:offline` объясняет это ограничение и не создаёт неработающий автономный файл.

## Как подключить ИИ

В этой рабочей копии уже может быть настроено локальное подключение. Повторно вводить ключ в таком случае не нужно. На новом компьютере или хостинге подключение настраивается отдельно от GitHub.

Рекомендуемый способ для хостинга — добавить переменные в его разделе **Environment / Переменные окружения**:

| Имя | Значение |
| --- | --- |
| `LLM_API_KEY` | API-ключ провайдера |
| `LLM_BASE_URL` | `https://generativelanguage.googleapis.com/v1beta/openai` — совместимый API Google Gemini |
| `LLM_MODEL` | `gemini-3.1-flash-lite` — проверенная модель для текущего подключения |

Затем перезапусти сервер. При изменении провайдера необходимо указать соответствующую модель. Подписка ChatGPT сама по себе не является API-доступом.

Для запуска на компьютере можно создать `.env` по образцу `.env.example` и использовать:

```bash
node --env-file=.env server.mjs
```

`npm start` сам по себе файл `.env` не читает. Уже настроенный локальный `.env.connection.json` формата `newapi_channel_conn` читается автоматически; его значения имеют приоритет над `LLM_*`. Он исключён из Git и Docker. Не добавляй ключ в исходники страницы.

Текущее подключение — прямой Google Gemini через его OpenAI-совместимый API, без ShareLLM. Это тот же сервис Gemini, но формат запроса подходит существующему серверному модулю. Нативный адрес `:generateContent` в `LLM_BASE_URL` вставлять не нужно. В проверке модель `gemini-flash-latest` сообщила о перегрузке (503); поэтому выбран рабочий вариант `gemini-3.1-flash-lite`.

Для прежнего ShareLLM можно явно указать `LLM_BASE_URL=https://sharellm.net/v1` и `LLM_MODEL=qwen3.8-flash` с соответствующим серверным ключом. Новые значения по умолчанию — Google Gemini; для ShareLLM адрес и модель необходимо задать явно. Локальный файл подключения имеет приоритет: для смены провайдера меняй его или убирай его со своего сервера перед настройкой `LLM_*`.

При использовании сетевого прокси нужен Node.js 24.5 или новее. Проверка TLS остаётся включённой. Сервер допускает ожидание до четырёх минут: сайт показывает ожидание и не отправляет повторный запрос при повторном нажатии. Ошибка модели сохраняет предыдущие задания; переключение на шаблоны остаётся доступным.

## Как проверить

Обычные проверки не обращаются к платной модели:

```bash
npm test
```

Они включают независимые расчёты для шаблонных заданий, исполнение заранее подготовленных Python-примеров из генератора, сравнение ответов и сценарии HTTP API с сервисом-заглушкой. Python-код посетителя или модели не исполняется. Требуется Python 3, доступный командой `python`.

Для проверки в настоящем Chromium при запущенном сервере:

```bash
python tests/browser.py
```

Для этой дополнительной проверки нужны Python Playwright и Chromium. Другой адрес сервера можно задать через `TEST_BASE_URL`, путь к Chromium — через `CHROMIUM_PATH`. Браузерные сценарии используют имитацию ИИ, а не реальный API-баланс.

Проверка настоящего подключения выполняется **отдельно**, с настроенным серверным ключом:

```bash
npm run test:llm
```

При подключении Google Gemini полный сценарий генерации, проверки и чата прошёл на модели `gemini-3.1-flash-lite`: 1,6 с, 1,0 с и 1,1 с соответственно в одном контрольном прогоне. Это небольшая проверка, а не гарантия скорости и качества на всех задачах. Прежний ShareLLM также проверялся и периодически возвращал 524. Подробности обоих подключений — в журнале экспериментов.

Она последовательно проверяет настоящие генерацию, оценку развёрнутого ответа и чат и может расходовать API-баланс. При ошибке останавливается; максимум три обращения к модели за успешный запуск. Успешные тесты с заглушкой и `aiAvailable: true` означают разные вещи: наличие настройки ещё не подтверждает реальную работу модели. Выполненные проверки и их ограничения записываются в [docs/EXPERIMENTS.md](docs/EXPERIMENTS.md).

## Будущие улучшения

- База данных вместо временной истории в памяти.
- Вход в аккаунт и синхронизация между устройствами.
- Больше экзаменационных тем и типов заданий.
- Расширенная математическая проверка и безопасная песочница для программ.
- Сравнение версий промптов на заранее размеченном наборе задач.
- Статистика качества и затрат на большом числе проверенных примеров.

Это планы, а не реализованные возможности. Модель может ошибаться; её оценка не заменяет преподавателя. Проверка рассуждений остаётся вероятностной даже при правильном формате JSON.

## Как сделать обычный сайт по ссылке

Размести приложение на **хостинге с Node.js**, который постоянно запускает сервер и выдаёт HTTPS-адрес. Например, в Render это тип сервиса **Web Service**. Подключается этот GitHub-репозиторий, команда запуска — `npm start`, переменная `HOST` — `0.0.0.0`, API-настройки вводятся в разделе переменных хостинга.

После успешного запуска получишь адрес вроде `https://имя-сайта.onrender.com`; его можно открыть на телефоне и отправить преподавателю. Собственный домен покупать необязательно. У посетителей не должно быть Node.js: им нужен только браузер. Хостинг и API модели — две отдельные услуги со своими тарифами.

Пошаговая инструкция находится в [DEPLOY.md](DEPLOY.md). GitHub хранит код; сохранение кода и публикация среды разработки сами по себе не создают постоянный сайт. Для этой версии простой статический GitHub Pages недостаточен, потому что задания, эталоны и проверка находятся на сервере.
