# exam-generator

Генератор практических заданий для подготовки к экзамену.

«Практикум» — рабочий учебный прототип курсового проекта «Генератор практических заданий для подготовки к экзамену с использованием промпт-инжиниринга».

## Скачать и открыть без установки

[Скачать готовый архив сайта](https://github.com/Weeqee05/exam-generator/raw/refs/heads/main/downloads/praktikum.zip). Распакуй архив и открой файл `praktikum.html` в браузере. Это автономная версия без ИИ; устанавливать Node.js и запускать сервер для неё не требуется. Сохранение истории локальных файлов зависит от настроек браузера.

[Скриншот на компьютере](downloads/praktikum-desktop.png) · [Скриншот на телефоне](downloads/praktikum-mobile.png)

## Текущие возможности

- Темы: комплексные числа, множества и отношения, основы Python.
- Три уровня сложности и от 1 до 10 заданий в варианте.
- Раскрываемые подсказки, ответы и объяснения.
- Новый вариант, отметка решённых заданий и история последних 20 вариантов.
- Восстановление прогресса в том же браузере через localStorage.
- Составление и копирование промпта с темой, сложностью, количеством заданий и форматом JSON.
- Поиск вариантов по теме, сложности и номеру, восстановление последнего открытого варианта.
- Скачивание варианта в TXT, печать и сохранение в PDF — с ответами или без них.
- Адаптивный русскоязычный интерфейс для компьютера и телефона.
- Подготовленное серверное подключение языковой модели через совместимый Chat Completions API.

Без ключа задания формируются по локальным шаблонам со случайными параметрами, а ответы вычисляются программно. Серверная версия использует ShareLLM с моделью `qwen3.8-flash`. На генерацию может понадобиться до четырёх минут. Когда сервер видит подключение, режим «С помощью ИИ» выбирается автоматически, а запрос отправляется после нажатия «Создать вариант». Вкладка «Промпт» показывает запрос для текущего варианта. Отметка «Решено» устанавливается самим пользователем: автоматической проверки введённых ответов нет.

## Требования

- Node.js 18 или новее и npm.
- При работе через `HTTPS_PROXY` / `HTTP_PROXY` — Node.js 24.5 или новее. Рекомендуется Node.js 24 LTS.
- Python 3, доступный командой python, для исполнения учебных Python-примеров в тестах. Для запуска сайта Python не требуется.

Внешних npm-зависимостей и отдельной сборки нет. Устанавливать пакеты для текущей версии не требуется.

## Запуск

Для открытия на компьютере без установки Node.js можно подготовить один автономный HTML-файл:

```bash
npm run export:offline
```

Открой полученный `downloads/praktikum.html` двойным щелчком в браузере. Внутри уже есть стили и код; дополнительных файлов, сервера и интернета не требуется. Доступны обычная практика, история, прогресс, промпты, скачивание и печать. Подключение ИИ требует серверной версии, описанной ниже. История привязана к браузеру и локальному файлу; перенос файла в другое место может изменить доступность сохранений.

В терминале из корня проекта:

```bash
npm run dev
```

Открой http://localhost:8000. Для остановки сервера нажми Ctrl+C.

Сервер можно запустить напрямую без npm:

```bash
node server.mjs
```

Сервер по умолчанию слушает только локальный интерфейс. Для хостинга задаются `HOST=0.0.0.0` и порт, предоставленный платформой. Для режима ИИ см. [.env.example](.env.example) и [DEPLOY.md](DEPLOY.md). Без этих настроек обычная практика полностью доступна.

Для встроенного предпросмотра среды запускай `HOST=0.0.0.0 EMBEDDED_PREVIEW=1 npm run dev`: сервер принимает подключения от прокси среды и разрешает отображение страницы во фрейме. Без `EMBEDDED_PREVIEW=1` встраивание заблокировано заголовком CSP. Сам интерфейс среды должен поддерживать подключение предпросмотра; эта настройка не создаёт публичный адрес сайта.

Сервер также автоматически читает локальный файл `.env.connection.json` с подключением формата `newapi_channel_conn`: поля `url`, `key` и необязательное `model`. Адрес вида `https://sharellm.net` преобразуется в `https://sharellm.net/v1`. Данные файла имеют приоритет над полями `LLM_*` среды, поэтому при таком подключении заполнять их вручную не требуется. Файл не включается в Git, Docker-образ и скачиваемый HTML.

## Проверки

```bash
npm test
```

Проверяются 945 сочетаний параметров и seed, 5040 расчётов, исполнение 1680 учебных Python-программ и события интерфейса через адаптер DOM. Дополнительно тестируется сервер: работа без ключей, передача промпта сервису-заглушке, ошибки, ограничения, валидация и безопасное отображение ответа модели, история и экспорт. Это не настоящий запрос к платному сервису ИИ.

Браузерная проверка использует дополнительный Python Playwright и Chromium. При запущенном `npm run dev` и установленном Playwright:

```bash
python tests/browser.py
```

По умолчанию используется `/usr/bin/chromium`; другой путь задаётся `CHROMIUM_PATH`. Проверяются пользовательские действия, восстановление истории, скачивание, печать и размеры экрана от 320 до 1440 пикселей. Ветка ИИ проверяется с имитацией API; реальный доступ к сервису нужно проверять отдельно после настройки ключа.

Явная проверка настоящего подключения к ShareLLM: `npm run test:llm`. Команда использует подключение из `.env.connection.json` либо `LLM_API_KEY` из окружения сервера и делает один реальный запрос на одно задание. Она не входит в `npm test`; обычные тесты и браузерные заглушки не расходуют API-баланс. Подробности настройки и проверки — в [DEPLOY.md](DEPLOY.md).

## Работа в Codex

Подключи этот репозиторий к окружению Codex. Сначала запусти npm test, затем npm run dev для просмотра приложения. Для текущей версии ключи API не нужны.

Серверное подключение модели и проверка полученного JSON работают; настоящий запрос к ShareLLM проверен отдельно от тестов с заглушками. Сравнение нескольких вариантов промптов на одинаковых параметрах задания остаётся отдельным этапом курсовой. API-ключи хранятся в настройках сервера и не попадают в браузерный код или Git.

## Размещение

Инструкция для обычной ссылки в браузере: [DEPLOY.md](DEPLOY.md). Есть Dockerfile и вариант запуска на Node.js-хостинге. Папка `dist/` также может работать на статическом хостинге в обычном режиме. В этой копии нет служебных настроек размещения Sites. Обновления репозитория сами по себе не обновляют первоначальный сайт; доступ к нему сохраняется отдельно.
